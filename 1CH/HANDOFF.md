## 2. 현재 동작 구조

### 2.1 좌표계 — 디스플레이 줌

`ScalerCrop` 을 센서 전체로 고정하고 줌은 출력 크롭으로만 처리한다.

**이유는 화질이 아니라 좌표계 안정성.** 하드웨어 줌 시절엔 줌 도중 `ScalerCrop` 이 계속
바뀌어 CAP 좌표계가 프레임마다 스케일됐고, 추적기·PTZ·속도추정을 매번 rebase 해야 했다
(반영에 7프레임 지연). 크롭을 고정하니 rebase 경로 4개를 전부 삭제했고, **줌 1.0→3.0
전 구간에서 추적 중심이 1px 만 움직였다.**

부수 효과: CAP 좌표계가 줌과 무관하게 불변 → 비동기 추적 결과에 `zoom_epoch` 같은
식별자가 필요 없다.

**CAP 픽셀 단위 상수는 `CAP_K = CAP_W/1920` 으로 스케일된다** (`PAN_STEP`,
`FOLLOW_LEAD_MAX`, `LFC_INIT_BOX`, `BOX_*`, `LFC_STAB_*`, `LFC_SCALE_*_PX`).
CAP 해상도를 바꾸면 이 상수들의 화각 의미가 달라지므로 반드시 함께 스케일돼야 한다.

### 2.2 스레드 구성

```
캡처 루프 (main)   cam.read → 안정화 추정 → 추적 결과 수거 → PTZ → 행렬 생성
Renderer           warp/크롭 + OSD + RTSP push          (최신 1장, 밀리면 버림)
LightFCTracker     Hailo backbone + head                (mailbox 깊이 1, 덮어쓰기)
RtspServer         GStreamer GLib 메인루프
snap_loop          USB 스냅샷 기록                       (큐 4, 넘치면 drop 카운트)
fcc_loop / gcs_loop 시리얼 / UDP
```

**렌더를 캡처 루프에서 분리한 이유.** 1080p warp 는 부하 상태에서 20ms 를 넘어 60fps
캡처 루프 예산(16.7ms) 안에 들어가지 않는다. 루프 안에 두면 프레임을 버리게 되고,
그러면 모션 추정 간격이 들쭉날쭉해져 고주파 진동이 접혀 들어와(aliasing) 젤리가 된다 —
**실측에서 60.9fps 가 22fps 로, `work_med` 0.2ms 가 41.6ms 로 갔다.**

표시 경로라 오래된 프레임을 붙잡느니 최신 프레임을 그리는 쪽이 항상 낫다. 밀린
프레임 수는 `/status` 의 `render.dropped`.

추적기 입력도 같은 이유로 **깊이 1 mailbox 덮어쓰기**다 (`self.pending = bgr`).
FIFO 큐면 추론 주기보다 지연이 길 때 적체된다.

### 2.3 영상 안정화 (`FrameStabilizer`)

오프라인 `stabilize_video.py` 와 같은 **4-DOF similarity**(a, b, tx, ty) 방식. dx/dy/da 가
아니라 행렬을 다루므로 드론 접근처럼 프레임간 스케일이 변하는 장면에서 zoom 을
translation 으로 오인하지 않는다.

**절대 경로 `A_i` 를 누적하지 않는다.** 프레임간 추정의 미세한 스케일 편향이 곱셈으로
쌓여 정지 화면에서도 발산한다 — **실측 80 프레임에 스케일 2.15 배.** 대신 보정 행렬 `W`
자체를 상태로 두고

```
W <- leak(W · step⁻¹)
```

로 갱신한다. `step⁻¹` 은 카메라가 움직인 만큼 화면을 되돌리고, `leak` 은 `W` 를 항등
쪽으로 시정수 `tau` 로 놓아준다 — **새는 적분기.** 편향이 쌓여도 leak 이 계속 지워내므로
발산하지 않고, 미래 프레임 없이 인과적으로 동작한다.

구성 요소와 각각의 이유:

| 요소 | 이유 |
|---|---|
| `_to_capture` 켤레변환 | stab(240x135)→capture 는 `diag(Kx,Ky)·W·diag(Kx,Ky)⁻¹`. 축 배율이 다르므로 그냥 복사하면 skew 가 들어간다 |
| soft wall (`STAB_WALL`) | 여유 한계에 가까울수록 tau 를 줄여 빨리 놓아준다. 없으면 매 프레임 하드 클램프에 걸렸다 풀렸다 하며 젤리가 된다 |
| 이분탐색 + anti-windup | soft wall 을 넘은 경우의 최후 안전장치. 6회 이분탐색으로 들어가는 배율을 찾고, `self.W` 도 같이 줄여 windup 을 막는다 |
| `_deadzone` | 추정 잡음 수준의 미세 보정을 버린다. 하드 임계가 아니라 크기에서 빼는 soft threshold 라 경계에서 튀지 않는다 |
| `hist` (낱개 step 보관) | 옛 측정을 현재 프레임으로 옮기는 `transport()` 용. **누적본이 아니라 낱개**를 들고 있다 — 누적하면 위의 스케일 편향이 곱해진다 |
| `_rolling_shutter` | 행 y 는 `(y/H)·T_r` 만큼 늦게 읽히므로 x 는 y 에 비례한 shear, y 는 세로 스케일 오차가 된다. 둘 다 affine 이라 warp 에 곱하면 된다. `STAB_RS_MS=0` 이면 꺼짐 |

**`STAB_FREE`(현재 운용값 1)**: 크롭으로 여백을 확보하는 대신 검은 테두리를 허용한다.
화각을 온전히 쓰지만 **완전 무제한은 불가능하다** — 지속적인 팬에서 보정량이
`속도 × tau`(**실측 3180px/s × 0.6s = 1908px**)까지 자라 화면이 통째로 날아간다.
`STAB_FREE_PX` 로 상한만 크게 열어둔다.

**`STAB_RATE` 는 낮추면 안 된다.** 30Hz 로 낮추면 고주파 진동에서 오히려 안 켠 것보다
나쁜 순간이 생긴다 — **실측: tap 영상 max 353px vs OFF 215px.** 전속 추정이 필요하다.
그래서 안정화 추정만 렌더(12fps)와 분리해 캡처 전속으로 돈다.

**`STAB_DC_TAU` 는 기본 꺼짐(0).** 의도한 팬을 step 의 DC 성분으로 보고 빼내는
방식인데, **실측상 손팬은 등속이 아니라 오히려 나빠졌다.**

### 2.4 추적 — LightFC on Hailo

`LFC_TEMPLATE_FACTOR` 배로 crop 한 템플릿과 `LFC_SEARCH_FACTOR` 배 검색 패치를 대조하는
**로컬 추적기**다. 전체화면 검출기가 아니다. 성격은 "저속이지만 누적 오차가 없는
외형 기반 로컬 측정값".

경로: `Hailo backbone` → `A_front.onnx`(상관 MatMul, CPU 잔류) → `lightfc_head_back.hef`(Hailo).

- 백본과 head_back 이 **별도 HEF = 별도 네트워크 그룹**이라 교대 실행 시 컨텍스트 전환이
  일어난다(§4). 없애려면 하나의 HEF 로 합쳐야 하는데 사이에 CPU 상관연산이 끼어 있어
  현재 구조로는 불가능하다.
- VDevice 는 `HailoSchedulingAlgorithm.ROUND_ROBIN`. **스케줄러 모드에서 `ng.activate()`
  를 호출하면 안 된다** — 기존 경로는 `LFC_HEAD_HAILO=0` 일 때만 activate.
- 출력 vstream 은 이름·순서에 의존하지 않고 **값 범위로 자동 판정**한다(`_map_outputs`):
  1채널 → score, 2채널·min≥0 → size(Sigmoid→Clip), 2채널·음수포함 → offset. §5 참조.
- 타임아웃은 **벽시계 기준** `LFC_MISS_SEC`. 갱신 "횟수" 기준이면 실효 갱신율이 설정값을
  못 따라갈 때 타임아웃이 같이 늘어난다(실제로 5.6초가 7.2초가 됐었다).

**크기(거리변화) 추종.** size head 를 쓰되 **기하평균에서 스케일 인자 하나**만 뽑는다
(종횡비 불변). `LFC_SCALE_LR` 감쇠 + `LFC_SCALE_RATE` 갱신당 변화율 상한을 걸어 회전
성분을 저역통과로 거른다 — 회전은 진동성이라 제자리로 돌아오고, 거리변화는 단조라
누적된다. 근거 수치는 §4.

크기를 고정하면 안 되는 이유: search crop 크기가 `sqrt(w·h)·4` 라 같이 고정되어,
다가오는 표적은 crop 을 넘어서면 소실되고 멀어지는 표적은 **점수가 0.91 로 오른 채
IoU 0** 으로 템플릿을 배경에 넘겨준다.

**다중 스케일 탐색(probe) 은 폐기했다.** peak score 에 스케일 판별력이 없다 —
crop 0.69x~1.44x 스윕에서 0.883~0.909 로 평평하고 최대값이 오답 쪽에 있다.
penalty·damping 까지 구현·측정했으나 정답 부근에 신호가 없다.

**템플릿 EMA 는 기본 꺼짐(`LFC_TPL_ALPHA=0`).** 근거는 §4. 필요해지면 맹목적 EMA 로
되돌리지 말고 **anchor 템플릿**(초기 `z0` 영구 보관 + EMA 가 `z0` 에서 멀어지면 하드
재고정)으로 갈 것.

`TargetTracker`(LK 광류)는 **Hailo 초기화가 실패했을 때만** 쓰이는 fallback 이다.
`/status` 의 `mode` 가 `lightfc` / `lk` / `none` 으로 구분한다.

### 2.5 표적 박스 평활과 지연 보정

세 가지가 겹쳐 있다. 각각 다른 문제를 푼다.

**(1) `LightFCTracker._stab()` — 표시 박스 lag 데드밴드.**
`_crop` 이 crop 원점을 `int(round())` 로 양자화하고 그 결과가 다음 프레임 crop 위치로
되먹임돼, 정지 장면에서도 박스가 랜덤워크한다. 스텝이 아니라 **raw 박스와 표시 박스의
누적 거리**에 데드밴드를 건다 → 정지 시 완전히 굳고, 느린 드리프트도 결국 따라가며
(정상상태 지연 = 데드밴드), 급기동(d ≥ SPAN)에서는 게인 1.0 이라 지연이 없다.
추적 내부 crop 은 **raw 박스**를 그대로 쓴다(추적 성능 불변). `snapshot()` 만 안정화
박스를 내보내므로 표시·PTZ 타깃·속도추정·예측이 모두 함께 조용해진다.

**(2) `box_smooth()` — 안정화 좌표계 데드밴드 + 속도 제한.**
**반드시 안정화 좌표계에서 비교해야 한다.** 센서 좌표에서 재면 카메라 흔들림
(**실측 p95 55px/frame**)이 매 프레임 데드밴드를 뚫고 지나가 평활 계수가 1.0 으로
포화돼 아무 효과가 없다. 그래서 평활 박스를 `stab.transport()` 로 현재 프레임 좌표로
옮긴 뒤 새 측정과 비교한다 — 이러면 차이에 표적 자신의 움직임만 남는다.
표적이 물리적으로 낼 수 없는 속도로 튀는 것은 추적기가 다른 물체로 옮겨갔다는 뜻이라
`BOX_MAX_RATE` 만큼만 따라간다.

**(3) 비동기 결과의 시간 정렬 + 갱신 사이 예측.**
추적 결과는 몇 프레임 전 좌표다. `stab.transport(t)` 가 그 사이 **측정된 프레임간
이동**(속도 예측 같은 근사가 아니다)을 곱해 현재 프레임 좌표로 옮긴다. 보정을 옛
측정에 그냥 씌우면 흔들림 p95 55px/frame 기준 **박스가 100px 이상 밀린다.**

그 위에 상수속도 외삽을 얹는다:

```
age      = clamp(now - t_result, 0, PRED_MAX_AGE)
pred_dx  = clamp(tvx * age, ±FOLLOW_LEAD_MAX)
제어 목표 = 중심 + pred + tvx * LEAD_TIME
표시 박스 = 중심 + pred
```

속도 추정 `tvx,tvy` 의 시간 기준은 **측정이 생성된 시각 `t_result`** 다. 프레임 시각이
아니다 — 표적은 추적 갱신 주기로만 바뀌므로 프레임 간격으로 나누면 갱신 없는
프레임에서 속도가 0 으로 끌리고 갱신된 프레임에서 과대평가된다.

속도·예측·PTZ 목표는 **전부 안정화 화면 좌표계**에서 다룬다. 그러지 않으면 크롭창이
흔들림을 따라가 떤다.

**(4) `FlowTracker` — 매 프레임 광류 전진 + LFC 앵커. 기본 꺼짐(`FLOW=0`).**
ROI 지정과 표적 획득은 LFC 가 한다. Flow 는 그 ROI 안에서 특징점을 만들어 매 프레임
박스를 전진시키고, LFC 결과가 도착할 때마다 앵커로 보정받는다. 역할이 갈린다:

```
LFC   누적오차 없음 / 24~30Hz / 결과가 1~2 프레임 묵음   -> 앵커, 크기, 재획득
Flow  매 프레임 실측 / 지연 없음 / 드리프트 누적          -> 프레임 사이 전진
```

- **크기는 Flow 가 건드리지 않는다.** LFC size head 쪽에만 실측 근거가 있고(§4.4),
  둘 다 크기를 움직이면 서로 싸운다. `set_size()` 로 받기만 한다.
- **앵커는 시간 정렬 후에 적용한다.** LFC 결과는 `t_frame`(그 결과가 실제로 본 프레임의
  캡처 시각) 것이다. 그 시점의 Flow 중심과 비교해 오차를 구하고, 이후 프레임들의 affine
  **선형부만** 곱해 현재로 옮긴다(변위라 평행이동 항은 곱하면 안 된다).
  이력에 저장된 중심값도 같이 보정한다 — 안 하면 다음 앵커가 보정 전 값을 기준으로 같은
  오차를 다시 계산해 왕복 진동이 생긴다.
- **`stab.transport()` 와 겹쳐 쓰면 안 된다.** Flow 는 화면상 총 이동(카메라+표적)을
  재므로 transport 를 또 씌우면 카메라 성분이 두 번 들어간다. Flow 가 모는 프레임에서는
  `box_s` 경로와 오버레이의 `Tb` 를 둘 다 건너뛴다. `lfc_t = _now` 가 되므로 `pred_age`
  도 자연히 0 이 되어 상수속도 외삽이 꺼진다.
- **표적이 커지면 우선순위가 뒤집힌다**(`LFC_BIG_FRAC`, 기본 0.25). 박스가 화면의 이
  비율을 넘으면 위치·크기를 모두 Flow 가 담당하고, `lfc.retarget()` 이 LFC 의 검색창을
  Flow 위치·크기로 끌고 간다. 안 그러면 LFC 가 표적을 놓친 자리를 계속 들여다본다.
  **크기까지 함께 넘겨야 한다** — 검색 패치가 박스 크기로 정규화되므로 커진 표적에 맞는
  크기라야 템플릿과 다시 맞아 재획득이 된다.
  `set_hold()` 는 그동안 저점수 타임아웃을 막는다. **Flow 가 살아 있을 때만** 켠다 —
  근거 없이 켜면 놓친 표적을 영원히 따라간다. GCS `clear` 는 언제나 통한다.
  기본값 0.25 의 근거: 검색 패치가 박스의 4배라 박스가 `CAP_H/4` 를 넘으면 패치가 프레임
  밖으로 나가 0 으로 패딩된다. 상관이 무너지기 시작하는 지점이 거기다.
- **Flow 무효면 하드 재고정**(`start()` 로 재시드). 소프트 블렌딩으로 끌면 틀린 상태를
  오래 끈다. 보정량이 박스 대각선의 `FLOW_RESEED` 배를 넘어도 같다.
  재고정도 실패하면 그 프레임은 기존 LFC 경로로 폴백한다.
- **놓치면 마지막 박스를 그 자리에 남긴다**(`LOST_BOX=1`). 조종수가 어디서 놓쳤는지
  보고 재획득할 수 있어야 한다. **센서 좌표에 고정**하므로 장면에 붙어 있고, 크롭창이
  움직이거나 안정화가 걸려도 화면에서 같은 장면 지점을 가리킨다.
  색으로 구분한다: 노랑=정상, 주황=저점수, **빨강=놓친 자리**.
  **표시 전용이다** — `set_fcc_target(False)` 그대로이고 `/status` 의 `track_box` 도
  `null` 이다. 죽은 값을 FCC LOS 나 GCS 로 내보내면 안 된다. 별도로 `lost_box` 에만 뜬다.
  새 클릭이나 GCS `clear` 로 지워진다. `LOST_BOX_SEC` 로 자동 소멸 시간을 줄 수 있고
  기본 0 은 지울 때까지 유지다.
- crop 창은 **매 프레임 박스 중심을 따라간다.** 고정하면 특징점이 1~2 프레임 만에 창
  밖으로 나간다(§5). 이월은 좌표 변환뿐이라 재검출 없이 그레이 변환 한 번이면 된다.

주의: score < `LFC_SCORE_MIN` 인 동안 `t_result` 가 멈춰 age 가 상한에 붙는다.
박스가 `v × PRED_MAX_AGE` 만큼 고정 오프셋을 갖지만 발산하지는 않는다.

### 2.6 출력·기록

- **RTSP** `rtsp://<ip>:554/video0`, eth0. GStreamer `appsrc → videoconvert → x264enc →
  rtph264pay`. `leaky-type=downstream`, 큐 3.
  `push()` 는 **클라이언트가 붙기 전에는 즉시 리턴**하므로 x264 가 아예 안 돈다(§5).
- **인코더 설정 근거**: "1초 주기 모자이크"는 비트 부족이 아니었다(CRF20 으로 1059kbps
  면 충분). **IDR 키프레임 버스트**가 원인 — 키프레임 하나가 RTP 패킷 87개로 몰려나가
  수신측이 흘리면 다음 키프레임까지 깨진 채 유지된다. intra-refresh 가 그 버스트를 없앤다.
  Pi 쪽 송신 무결함 확인됨(로컬 수신 디코딩 오류 0, UDP/eth0 드롭 0). **증상이 남으면
  수신측 문제다.**
- **리샘플링**: `warpAffine(INTER_LINEAR)` 이 아니라 정수 크롭 + resize, 축소 `INTER_AREA` /
  확대 `INTER_CUBIC`. INTER_LINEAR 은 2x2 이웃만 봐서 3배 축소 시 화소 대부분을 버리고,
  그 에일리어싱이 **고주파 에너지를 2배(254.7 vs 130.8)로 올려** H.264 가 감당 못 한다.
- **USB 스냅샷**: 클릭 시점 원본 프레임을 `/mnt/usb/snap` 에 JPEG + `index.jsonl`.
  마운트·여유공간 확인, `.part` → `os.replace` 원자적 교체, `fsync`. 큐(4)가 넘치면
  캡처를 막지 않고 `drop` 카운트만 올린다.
- **GCS**(UDP 37260) / **FCC**(시리얼 45B TX / 96B RX, 50Hz). `CMD_AI_MODE`(show_det)
  는 프로토콜 호환을 위해 파싱만 남아 있고 **아무 동작도 하지 않는다** (YOLO 제거됨).
- `/status` 는 `STATUS_FILE` 로 `/dev/shm/gimbal-status.json` 에 `STATUS_EVERY` 프레임마다.

| 실카메라 40프레임 반복, 강텍스처 | **12.5 px** | **1.2 px** |

EMA 는 박스가 지금 담고 있는 것을 그대로 재학습하므로 작은 정렬 오차가 템플릿에
구워지고 다음 프레임 오차를 키운다(self-reinforcing drift). 부수 효과로 스케일 추종도
좋아졌다(approach 최종 IoU 0.86 → **0.93**) — 템플릿이 고정이라 hint 가 1 로 수렴하지
않기 때문. 회전 breathing 은 5→3% / 12→14% 로 사실상 불변.

**EMA 가 스케일 적응을 방해하는 경로**: 템플릿은 박스의 `LFC_TEMPLATE_FACTOR` 배로
crop 하므로 박스가 작은 채로 EMA 를 돌리면 표적을 작게 재학습해 hint 가 1 로 수렴한다
(score 0.91 인 채 박스가 안 큼). 스케일이 움직이는 동안(`|f-1| > LFC_SCALE_HOLD`) EMA 를
멈추는 한 줄로 approach 최종 IoU 가 **0.54 → 0.86** 이 됐다.

### 4.5 Flow + LFC 앵커 (합성 시퀀스, 2026-08-28)

배경 실촬영 + 텍스처 패치 표적(100x100) + 카메라 셰이크(7.3Hz 26px, 6.1Hz 19px),
240 프레임 60fps. LFC 는 **30Hz, 2프레임 지연, 측정잡음 sigma 1.5px** 로 모사.
비교군 "LFC 단독" 은 지연된 최신 측정을 그대로 쓰는 것(현재 동작의 근사).

| 기준 15.5px/frame | **1.30 / 3.33** | 32.48 / 59.78 | 0 | 0 |
| + LFC 0.5s 두절 | **1.37 / 4.05** | 34.01 / 66.00 | 0 | 0 |
| 빠른 이동 28px/frame | **1.26 / 38.72** | 52.73 / 120.17 | 10 | 6 |

표적에서 드리프트 보정이 느려진다:

주의: 센서 좌표에서 재면 정지 표적도 프레임간 16px 씩 움직인다(카메라가 흔들리므로
실제로 그렇다). 떨림은 반드시 안정화 좌표에서 잴 것 — 이 함정에 한 번 빠졌다.
- **앵커 없이 Flow 단독은 med 25.1px 로 흐른다.** 표류가 실재하므로 앵커가 필수다.
- **빠른 이동 + 회전에서 Flow 가 거의 매 프레임 죽는다**(하드재고정 63/240). 그래도
  폴백이 걸려 LFC 단독보다는 낫다(med 21.95 vs 65.03).
- `update()` 비용: med 1.5~2.6ms / p95 2.8~4.7ms (CM5, 서비스 구동 중).

## 5. 함정 — 전부 실제로 밟은 것

- **HailoRT 포맷은 반드시 `FormatType.FLOAT32`** 로 지정한다(입력·출력 모두). 기본값이
  양자화된 uint8/uint16 이라 그대로 쓰면 추적이 통째로 어긋난다.
- **HEF 출력 vstream 이름을 믿지 말 것.** `HAILO_0B_RESULT.md` §8 은 `output_layer1/2/3`
  이라고 적었으나 실물은 `activation1` / `activation2` / `conv14` 였다. 게다가 `size_map`
  과 `offset_map` 은 둘 다 `(16,16,2)` 라 shape 로 구분되지 않는다. **두 번 당했다.**
  → 값 범위로 판정(`_map_outputs`, `validate_0b.py` 동일).
- **head_back 입력은 NHWC**, 채널 수로 구분한다 (64 = 상관출력, 96 = 원본 fx).
- **`RtspServer.push()` 는 클라이언트가 없으면 즉시 리턴한다.** x264 가 아예 안 도므로
  시청자 없이 잰 수치와 GCS 붙은 수치를 비교하면 안 된다 — 44Hz 와 27Hz 를 비교하고
  기록기 탓이라고 오진한 적이 있다(실비용은 27.3 → 25.7Hz). **절대 수치를 인용할 때는
  시청자 유무를 반드시 같이 적을 것.**
- **`/status` 의 `ms` 필드는 마지막 1회 샘플이다** (중앙값 아님). `ms=103.3` 을 대표값으로
  읽고 "실효 9.68Hz" 라고 판단했으나 실제 중앙값은 60ms 대, 103ms 는 p95 부근 꼬리였다.
- **`json.dumps` 와 numpy 스칼라.** 박스의 `w,h` 는 size head 출력이라 numpy `float32`
  였고 **박스가 움직인 프레임에서만** 직렬화가 터졌다. 빈 `except` 가 삼켜서 540 프레임
  중 250 행이 조용히 사라졌는데 **하필 표적이 움직인 구간만** 없어졌다.
  → `_infer` 가 Python float 만 반환하도록 고쳤고 **이 수정은 남아 있다.**
  `set_track_box` 가 예전부터 `round(float(v), 1)` 로 방어하던 건 전에도 밟았다는 뜻이다.
  추적기 상태를 JSON 으로 내보낼 때 항상 의심할 것.
- **예외를 조용히 삼키지 말 것.** 실패 카운터를 `/status` 에 노출할 것.
- **`_bye` 가 `os._exit(0)`** 이라 종료 시 버퍼가 안 비워진다. 파일을 쓰는 기능을 붙이면
  시그널 핸들러에서 명시적으로 flush 해야 한다.
- **LK 의 `prevPts` 는 이전 영상 좌표계여야 한다.** 현재 ROI 로 보정한 점을 넘기면 안
  된다(초기 추정은 `OPTFLOW_USE_INITIAL_FLOW` 로). 이 버그로 벤치의 이동 케이스가 전부
  깨졌었다. RANSAC 에는 CAP 좌표로 변환한 점을 넣는다.
- **`dx,dy` 를 affine 의 `tx,ty` 로 해석하면 안 된다.** 회전이 있으면 평행이동 항은 중심
  이동량과 다르다. 중심에 행렬을 적용해서 구할 것.
- **LK status 0 인데 변위는 정확하면 피라미드를 의심하라.** 200x200 crop 에
  `maxLevel=3` 이면 최상위가 25x25 인데 창이 21x21 이라 대부분의 점이 경계를 넘는다.
  변위값 자체는 맞게 나오므로 "LK 가 못 따라간다"로 오진하기 쉽다.
- **Flow 의 crop 창을 고정하지 말 것.** 표적이 16~25px/frame 로 움직이면 1~2 프레임
  만에 특징점이 창 밖으로 나가 LK status 가 24점 -> 2점으로 무너진다. 창을 매 프레임
  박스 중심으로 옮기고 점은 좌표 변환으로 이월한다(재검출 불필요).
- **추적기 벤치의 합성 표적은 텍스처를 확인하고 쓸 것.** 저텍스처 패치를 쓰면
  200x200 crop 전체에서 코너가 5개만 잡혀 **추적기가 아니라 픽스처를 시험하게 된다.**
  코너 수로 패치를 고르면 된다. 실제로 이걸로 한 번 오진했다.
- **`.gitignore` 화이트리스트** — 새 파일은 명시하지 않으면 추적되지 않는다(§0).
- 손실 압축(H.264) 으로 저장한 프레임으로 LK 를 평가하지 말 것. 블록 아티팩트와 ringing
  이 코너·gradient 에 영향을 준다.

## 6. 검증되지 않은 것

- **`LFC_SCORE_MIN=0.60` 재도출 미완.** 양자화 후 score 분포가 달라진다. 뒤집힘 0/256,
  순위상관 0.99 라 크게 움직이진 않을 것으로 보이나 전제하지 말 것. 실기 기록 필요.
  현 캘리브 데이터(`/home/gimbal/lfc_calib`, 256 샘플)는 score>=0.60 이 **40개뿐**이라
  이 데이터로는 못 한다 — 실내 렌즈 무한대 고정(§1) 때문이다.
- **크기 추종·회전 breathing 은 전부 합성 시퀀스 검증이다.** 실제 3D 접근/후퇴의
  원근·자세변화·자기가림 없음. 회전 테스트도 2D 면내 회전이다.
  실기 카메라로는 스케일 적응 경로를 태우지 못했다.
- **Flow + LFC 앵커는 합성 시퀀스 검증만 했다**(§4.5). 실기 표적으로 태운 적이 없고,
  기본값이 `FLOW=0` 이다. 셰이크도 정현파 합성이라 실제 기체 진동의 스펙트럼과 다르다.
- **회전 12% breathing 이 실제 운용(제어 루프·조작자 체감)에 어느 정도 지장인지 미확인.**
- **§2.5 의 지연 예측은 실기 표적으로 shadow 검증 전이다.** 제어 개선을 단정하지 말 것.
  검증한 것은 계산 정합성뿐이다 (v=10.8px/s, age=150ms → dx=1.62, 보고값 1.6).
- **`TAU_FOLLOW=0.065` 재튜닝 여지.** 데이터가 신선해졌으므로 더 공격적으로 갈 수 있으나
  **실기 없이 바꾸지 말 것.**
- **표적 회전이 면내인지 면외인지 모른다.** `estimateAffinePartial2D` 는 유사변환이라
  면내 회전만 표현한다. 실기 데이터는 "회전에 약하다"는 관찰 한 줄뿐이고, 얼마나 자주
  어떤 각속도에서 운용에 얼마나 지장인지 수치가 없다.
- `CV_THREADS=2` 채택 근거는 **단회 측정**이고 폭이 작다(사이클 p95 111.5→99.2ms,
  갱신율 +7%). 저전압 이력을 감안하면 노이즈 범위일 수 있으나 4개 지표가 같은 방향이라
  채택했다.
