1CH_SUPER 타게팅 불능 원인 분석 및 수정 (2026-09-03)
=====================================================

증상
----
- RTSP 영상 송출은 정상인데 GCS에서 타게팅(추적 박스 지정)이 전혀 안 됨.
- 로그(lat_*.csv)상 서비스 기동 이후 상태가 IDLE에서 한 번도 벗어난 적 없음.
  9/1 로그 포함 과거 로그 전부 동일 → 간헐 문제가 아니라 1CH_SUPER에서
  타게팅이 동작한 적 자체가 없었음.

근본 원인
---------
- 8/29 영상 안정화 구현 때 fast_loop의 view_now()가 (z, ox, oy) 3개 반환에서
  (z, ox, oy, warp) 4개 반환으로 바뀜 (안정화 워프 행렬 추가).
- GCS UDP 명령 핸들러 GcsLink._track_action()은 그대로
  "z, ox, oy = self.view()" 3개 언패킹 → 추적 명령이 올 때마다 ValueError.
- 이 예외가 UDP 수신 루프의 "except Exception: pass"에 삼켜져
  로그 한 줄 없이 명령이 폐기됨. 줌/하트비트 등 다른 명령은 view()를
  안 쓰므로 정상 → "영상은 나오는데 타게팅만 조용히 전멸" 증상.

진단 경로
---------
- tcpdump로 eth0 UDP 37260 캡처 → GCS(192.168.144.201)에서
  CMD_TRACK_ACTION(0x06, 19바이트, 박스 좌표 포함)이 정상 도착함을 확인.
- 명령은 도착하는데 상태 전이가 없음 → 핸들러 내부 무음 실패로 좁힘 →
  view_now() 반환값 개수 불일치 발견.

수정 내용 (digital_gimbal.py)
-----------------------------
1) _track_action: 4개 언패킹으로 수정. 클릭 좌표 역매핑도 단순 근사식 대신
   crop_matrix + 안정화 warp 역행렬을 쓰는 정확한 역변환으로 교체
   (warp 없을 때 기존 수식과 수학적으로 동치 확인). 이제 안정화로 화면이
   흔들려도 클릭 위치가 원본 프레임 좌표로 정확히 매핑됨.
2) UDP 수신 루프의 except: pass → stderr 로깅 추가 (다음부턴 journal에 보임).
3) CameraV4L2: /dev/video0 고정 인덱스 → 열리는 캡처 노드(/dev/video0~15)
   자동 탐색. USB 카메라가 재열거되며 video0→video1로 밀려 크래시 루프에
   빠졌던 문제 해결.

수정 내용 (digital-gimbal-super.service)
----------------------------------------
- ExecStartPre=+gimbal-camera-ready.sh ('+' 추가). User=gimbal 권한으로는
  /sys/bus/i2c/drivers/imx708/bind 쓰기가 거부되어 스크립트가 무력화돼 있었음.

검증 (2026-09-03 라이브)
------------------------
- 수정 후 GCS 타게팅 → TRACK 상태 진입 확인 (349프레임, 30fps 유지,
  NanoTrack 5~6ms, 안정화 3~4ms, 예산 내).

남은 문제 (이번 수정 범위 밖)
-----------------------------
- imx708 CSI 카메라가 i2c 버스 10에서 완전 무응답(-121, 센서+VCM 둘 다,
  부팅 직후부터). dtoverlay 설정은 정상 → FFC 케이블/전원 등 물리 점검 필요.
  해결 전까지 USB(UVC) 폴백으로 동작.
- 추적 중 ANCHOR_FAIL 반복: SP 앵커 등록 실패(작은/저특징 타깃 + 실내 렌즈
  무한대 초점). 앵커 없으면 3Hz 감사/스냅백/재획득 안전망 없이 NanoTrack
  단독 동작. 기존 대기열 1번(타깃 주변 크롭 SP) 작업으로 해결 예정.
- GCS가 5초마다 보내는 cmd=0x0b 패킷은 핸들러에 정의가 없어 무시됨(무해 추정).
